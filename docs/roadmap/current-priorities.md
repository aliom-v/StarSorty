# 当前优先级

更新时间：`2026-03-28`

本文档只回答“下一步先做什么”。当前事实、风险和边界统一看 `../guides/engineering-audit.md`；需要展开到实施步骤时，再看 `optimization-execution-plan.md`。

## 当前焦点

### P0: 固化管理员会话与部署边界

为什么优先：

- 当前代码已收口 cookie session + CSRF，但公网部署仍依赖 same-site、HTTPS 和反向代理配置纪律
- 这是最容易出现“代码没错、部署错了”的部分

下一步：

1. 把管理员登录、cookie、CSRF、同域 `/api` 与 HTTPS 约束继续固化到部署模板和运维检查项
2. 继续观察 CLI / scheduler 是否仍应长期保留共享 `X-Admin-Token` 模型

### P1: 补齐 `/repos` 共享缓存治理

为什么优先：

- 当前已经有 SQLite 共享缓存值，但还缺尺寸治理、主动清理和观测
- 这决定后续是否真的需要独立缓存层

下一步：

1. 给 `cache_entries` 增加清理与上限策略
2. 增加缓存体量和命中来源观测

### P2: 统一开发与测试运行时基线

为什么优先：

- 当前验证链路仍受 Python 版本、Docker fallback、IPC 与本地端口能力影响
- 新环境接手项目时，环境问题仍然可能先于业务问题暴露

下一步：

1. 继续保持根目录脚本作为唯一推荐验证入口
2. 收紧运行时说明，减少 README、CONTRIBUTING、脚本文档之间的重复和漂移

### P3: 只有在数据证明需要时，再评估外部缓存或多节点

前提：

- 先完成共享缓存治理
- 先确认瓶颈确实来自共享缓存或共享状态，而不是部署方式或写入高峰

## 暂不优先

- 新功能扩展
- 更激进的 UI 重做
- 在导出内存模型和单实例边界未收口前继续扩大管理台能力
