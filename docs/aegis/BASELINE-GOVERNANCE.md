# Baseline Governance

Baseline documents capture the local architecture assumptions used by an implementation plan. They are not product requirements and should be updated only when a plan depends on new or changed architectural facts.

Rules:

- Prefer existing product docs for user-facing behavior.
- Keep baseline notes factual and source-linked.
- Update the active plan if an implementation contradicts the baseline.
- Verification evidence belongs in plan notes or final task output, not in baseline docs.
